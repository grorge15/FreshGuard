# 2026-10-08：事件系统参考文档与源码的差异

本次为框架用途说明，只核对源码，没有修改事件系统实现。以下结论基于当前仓库源码；未运行事件功能测试。

## 1. 全局分发与监听生命周期管理

- **问题现象**：把 `GameEventMgr` 和 `AddUIEvent` 理解成独立的局部事件通道，可能导致多对象监听同一 ID 时消息串扰。
- **文档位置**：`references/event-system.md` 的“架构概览”和“模式对比”；`references/ui-lifecycle.md` 的“UI 内部事件”。
- **正确 API**：`GameEventMgr.AddEvent` 调用全局 `GameEvent.AddEventListener`，`Clear` 批量移除其记录的全局监听；`UIBase.AddUIEvent` 调用此管理器。`UIWindow.InternalDestroy` 清理监听，单纯隐藏并不执行此清理。`new EventDispatcher()` 或 `new EventMgr()` 的分发器才有独立的监听表。
- **建议修正**：区分“局部管理监听生命周期”与“局部消息作用域”；不要用“UI 内部”暗示消息仅在该窗口传播。

## 2. 接口初始化及注册方法

- **问题现象**：文档称未初始化接口事件会无响应、无报错，并称生成的 `GameEventHelper` 提供 `RegisterListener<T>()`。
- **文档位置**：`references/event-system.md` 的“架构概览”“接口事件”和“常见错误”；`references/event-antipatterns.md` 的“反模式 4”。
- **正确 API**：`EventMgr.GetInterface<T>()` 查不到时返回 `default(T)`；对返回的 null 接口直接调用方法会产生空引用异常。仓库 `Tools/GameEventSourceGenerator/SourceGenerator/Generator/EventInterfaceGenerator.cs` 只生成 `GameEventHelper.Init()`，创建发送代理，并通过 `RegWrapInterface<T>` 注册代理；不生成 `RegisterListener<T>()`。业务接收方仍需注册委托。`RegWrapInterface` 使用 Dictionary.Add，因此重复 Init 并非幂等。
- **建议修正**：解释接口发送代理和业务监听的区别；删除当前生成器没有提供的 API；区分“代理未初始化”与“已初始化但无人监听”。

## 3. 事件组不构成消息隔离

- **问题现象**：文档称 `EEventGroup` 用于隔离模块，并示例使用当前不存在的 `GroupBattle`。
- **文档位置**：`references/event-antipatterns.md` 的“反模式 5”。
- **正确 API**：当前 `EEventGroup` 仅有 `GroupUI` 和 `GroupLogic`；仓库事件生成器筛选特性名称，但没有读取事件组参数来分流，生成代理统一使用 `GameEvent.EventMgr.GetDispatcher()`。
- **建议修正**：说明当前组值是分类信息，不是场景、对象或模块实例的路由作用域。

## 4. 委托签名不匹配的实际行为

- **问题现象**：文档称发送与监听泛型参数不一致会抛 InvalidCastException。
- **文档位置**：`references/event-system.md` 的“常见错误 4”；`references/event-antipatterns.md` 的“反模式 6”。
- **正确 API**：`EventDelegateData.Callback` 使用 `d is Action<T...>` 检查兼容委托，检查不通过时跳过该回调，没有强制转换异常。仓库另有 `GameEventAnalyzer` 源码可检查部分生成事件 ID 的调用；是否生效取决于分析器实际加载及可解析范围。
- **建议修正**：描述为可能静默漏收；接口发送具有编译期签名约束，但底层 int/Delegate 分发器本身不强制校验事件签名。

## 5. UI API 与 RuntimeId 的约束

- **问题现象**：文档示例用 `AddUIEvent(string, ...)`，并将自定义 ID 的数值范围约定与 RuntimeId 自动分配混在一起。
- **文档位置**：`references/event-system.md` 的“string 事件类型”和“事件定义规范”。
- **正确 API**：当前热更 `UIBase.AddUIEvent` 仅支持 int ID，0～4 个参数；字符串可先用 `RuntimeId.ToRuntimeId` 转换。`RuntimeId` 从 0 开始递增分配并缓存，不是稳定哈希，不保证从 10000 起分配，也不保证跨运行值一致。
- **建议修正**：修正字符串 UI 示例；生成事件统一用生成常量，不将 RuntimeId 存档或当作网络协议编号，也避免与手写数字 ID 混用。
